# المرحلة السادسة — نتائج اختبار القبول ومقارنة المصدر
**التاريخ:** 12 أكتوبر 2026  
**الموقع:** https://imadtbn.github.io/dz_portal/  
**المستودع:** imadtbn/dz_portal

## القرار الحالي

**المرحلة السادسة منجزة على مستوى التدقيق الساكن وأدوات اختبار المتصفح والإصلاحات المكتشفة، لكن قبول أداء الهاتف النهائي لم ينجح بعد، لأن اختبارات Chromium المباشرة وبيانات الأداء الجديدة غير متاحة من هذه الجلسة، ولأن هناك خللًا موثقًا في أحجام أيقونات PWA.**

لا تنسب لهذا التقرير قياسات CLS/LCP/FCP/INP لم يتم جمعها فعليًا.

## 1. فحص المصدر الذي نُفذ الآن

نُفذ فحص مبرمج لملفات المستودع الحالية ونجحت **28 من أصل 28 عملية تحقق ساكنة**: استمرارية تعريفات AdSense في الصفحات الخمس الأعلى أولوية، أعداد بطاقاتها، التخطيط الشبكي للإحصائيات، وجود البحث المحلي والعام، حارس تحميل البحث، شيفرة تثبيت PWA، تسجيل Service Worker، وتعريف نطاقه، وصحة صياغة أربعة ملفات JS، وصحة صياغة أداة الاختبار واختبار Node الجديد.

هذا الرقم **لا يعني** أن 28 اختبارًا تفاعليًا اجتازها متصفح الهاتف؛ اختبارات Chromium الحقيقية لم تُشغَّل هنا بسبب عدم قدرة بيئة تشغيل Chromium على الوصول إلى الإنترنت.

## 3. الانحدارات المكتشفة ومعالجتها

### أ. تحميل بحث عام بلا داعٍ في صفحات القطاعات — تم تصحيحه

- كان `deferred-homepage.js` يربط زر `.search-trigger` بتحمـيل `searchData.js` العامة (نحو 518 كيلوبايت من الشيفرة النصية) في صفحات لديها بالفعل محرك بحث محلي `localSearch.js`.
- أصبح تحميل الفهرس العام مقتصرًا على الصفحات التي تستضيف البحث العام `#globalSearch` أو عناصر `#searchResults` المتوافقة؛ ويُترك زر `.search-trigger` في صفحات القطاعات لمحرك البحث المحلي.
- تم تعديل `assets/js/deferred-homepage.js` وإضافة حارس في الاختبار.

### ب. دعم لوحة المفاتيح لتثبيت PWA — تم تصحيحه

- زر التثبيت الأصلي هو عنصر `div[role="button"][tabindex="0"]`، وكان يعتمد على `click` دون تنشيط Enter/Space.
- أضيفت معالجة `keydown` ضمن `assets/js/main.js` تستدعي نفس وظيفة النقر، دون تغيير المظهر أو النصوص.

### ج. فيديو `arpce2.html` — اكتمل تصحيحه

- تم إضافة `width="560"` و`height="315"` إلى `iframe` الذي سبق أن تعذر تعديله في المرحلة الرابعة.
- أضيفت الصفحة إلى `tests/cwv-mobile-media.test.js`.

### د. أيقونات PWA — خلل مؤكد لم يُصلح ثنائيًا بعد

- كشف فحص ترويسة PNG في GitHub أن `icon-192.png` و`icon-512.png` متطابقان وأن الحجم الحقيقي لكليهما **384×384 بكسل**.
- بينما يُعلن `manifest.json` حجمي **192×192** و**512×512**. قد يؤثر هذا على معايير قابلية تثبيت PWA؛ يجب عدم اعتباره اجتاز التحقق.
- أضيف اختبار يقرأ أبعاد IHDR الفعلية في `tests/cwv-stage6-acceptance.test.js`، وسيفشل حتى تُرفع الأيقونات الصحيحة.
- أضيفت أداة `tools/build-pwa-icons.py` لإعادة توليد المقاسين من شعار البوابة الحالي، باستخدام Pillow، مع الحفاظ على الرسم نفسه. **لا توجد صور مصححة ثنائية مرفوعة بعد إلى المستودع**؛ لا تدّعي هذه المرحلة إغلاق الخلل.

## 4. اختبار المتصفح التفاعلي المُعد

أضيف `tools/mobile-regression.mjs` إلى المشروع، و`qa:mobile` إلى `tools/package.json`، وتجاهل `mobile-qa-output/` في `.gitignore`. يغطي:
- 7 صفحات ممثلة و4 عروض هاتف 320، 360، 390، 412 بكسل (28 حالة)، أو `--quick` للاختبار المختصر.
- صور `initial.png` و`settled.png` و`after-scroll.png`، وتسجيل CLS/LCP/FCP المختبرية.
- فائض العرض الأفقي، صف إحصائيات Hero، أبعاد الهيدر والهيرو.
- عمل البحث العام وفلتر الخدمات الجديدة، والبحث المحلي وإغلاقه باستخدام Escape وروابط الأقسام.
- تحميل الملفات CSS بلا تكرار، وموارد PWA ونطاق Manifest، والتأكد من تسجيل Service Worker وتفعيلها.
- أحجام صور PWA الحقيقية مقارنة بما أُعلن في Manifest.
- تسجيل وضع طلبات AdSense وعرضها، والأخطاء البرمجية وطلبات الموارد المحلية الفاشلة؛ **لا يُعد عدم ملء الإعلان دائمًا فشلًا برمجيًا**.
- مقارنة اختيارية مع نسخة قديمة منشورة بواسطة `--baseline-url`، مع الحفاظ على المخرجات منفصلة.

### أوامر تشغيل مستقلة — لا توجد GitHub Actions جديدة

```bash
node --test tests/cwv-content-visibility.test.js tests/cwv-ads-stability.test.js tests/cwv-mobile-media.test.js tests/cwv-loading-stage5.test.js tests/cwv-stage6-acceptance.test.js

cd tools
npm install
npx playwright install chromium
npm run qa:mobile
npm run audit -- --all-widths --compare-ads
```

للمقارنة الحقيقية: شغّل النسخة القديمة على خادم منفصل ثم استعمل:

```bash
npm run qa:mobile -- --baseline-url=http://127.0.0.1:8081/dz_portal/
```

توجد المخرجات في `tools/mobile-qa-output/summary.md` و`tools/cls-audit-output/summary.md` والصور وملفات JSON.

**ملاحظة:** اختبار Node الجديد يتوقع أبعاد أيقونات PWA الصحيحة، لذلك سيفشل بند PNG حاليًا لحين توليد ورفع الملفات. ويتطلب الاختبار التفاعلي Chrome متصلًا بالموقع؛ لم يتم تشغيله في هذه الجلسة.

## 5. ما الذي لم يتحقق بعد؟

1. قياس CLS الفعلي عند 75th percentile في Search Console بعد نشر التغييرات لمدة كافية، ومقارنته بقيم التقرير الأولية (0.45، 0.31، 0.28، 0.27، إلخ).
2. تشغيل Chrome على 320/360/390/412px مع الإعلانات الحقيقية وإتمام فحوصات البحث والقوائم والفيديو والخطوط وPWA عمليًا.
3. مقارنة FCP وLCP وINP قبل/بعد، لأن جعل CSS والخطوط حاجبة للرسم في المرحلة الخامسة قد يعالج اختلاف الشكل لكنه قد يزيد وقت الرسم الأول.
4. رفع ملفي الأيقونات الحقيقيين بحجمي 192 و512 بكسل، وتحقق الاختبار من مطابقة Manifest.

**حالة خطة CWV: لا يمكن إعلان القبول الكامل حتى ينجح الاختبار الحي ويزول خلل أيقونات PWA؛ أما تحسن CLS في بيانات المستخدمين فلا يمكن إثباته إلا عند تحديث Search Console.**
