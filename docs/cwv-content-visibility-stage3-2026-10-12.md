# المرحلة الثالثة: استقرار ارتفاعات البطاقات والأقسام (2026-10-12)

## الهدف

تجنّب تحركات CLS التي قد تنشأ من `content-visibility: auto` مع `contain-intrinsic-size` تخميني يختلف عن ارتفاع المحتوى المتجاوب. لا يُعدّ هذا إثباتًا بأن هذه القواعد كانت السبب الوحيد للـ CLS، بل إزالة موضع خطر موثّق في الشيفرة.

## التغييرات المحدودة

| الملف | قبل | بعد |
| --- | --- | --- |
| `assets/css/style-main.css` | `.sector-card { content-visibility: auto; contain-intrinsic-size: 300px }` | بطاقات بارتفاع المحتوى الطبيعي مع إبقاء Flex وجميع الألوان والهوامش والأنيميشن |
| `assets/css/style-sector.css` | `.services-grid { content-visibility: auto; contain-intrinsic-size: 1px 1000px }` | ارتفاع حقيقي لكل شبكة خدمات مع بقاء عدد الأعمدة وتصميم البطاقات |
| `assets/css/performance-home.css` | محتوى `.sectors-section, .seo-tags, .stats-panel, .footer` يُتخطى في الهاتف مع تقدير `800px` | التخطيط يحسب الأبعاد الحقيقية من البداية |
| `assets/css/style-train-gallery.css` | `.train-card` بارتفاع تقديري `350px` | بطاقات الجداول تُقاس بناءً على النصوص والصور والأزرار الحقيقية |

لم تُضف قواعد `height` ثابتة ولم تُخفَ أقسام ولم تُحذف عناصر HTML. لم يتغير سكريبت تحميل الإعلان أو حجز مساحته المعتمد في المرحلة الثانية.

**ملحوظة عن الموازنة:** إيقاف تخطي العرض لهذه العناصر يعني أن المتصفح سيرسم عددًا أكبر من البطاقات أثناء التحميل الأول، وهو اختيار مقصود لتجنب اختلاف الأحجام التقديرية. يجب متابعة LCP وINP ووقت الرسم بعد النشر بدل افتراض تحسّن جميع المقاييس.

## التحقق من المصدر بعد التعديل

- اختفت تصريحات `content-visibility:auto` و`contain-intrinsic-size` من الملفات الأربعة المذكورة.
- لا تزال `.sectors-grid` تستخدم `display:grid`، و`.sector-card` تستخدم `display:flex`.
- لا تزال `.services-grid` تستخدم `display:grid` و`.service-item` تستخدم `display:flex`.
- بقيت إعلانات `adsbygoogle` وقواعد حجز مساحتها في الملفين الأساسيين `style-main.css` و`style-sector.css`.
- ثابتة في عينات التحقق الشيفري: **88** بطاقة قطاع في `index.html`، و**29** عنصر خدمة في `sectors/education.html`، و**36** بطاقة جدول في `sectors/sntf.html`.
- تم إنشاء `tests/cwv-content-visibility.test.js` للتحقق آليًا من عدم عودة القواعد التخيلية ومن بقاء تنسيقات المكونات. جرى فحص منطق الشروط على الملفات الحالية وفحص تركيب الاختبار؛ لم يُشغَّل `node --test` داخل نسخة محلية كاملة من المستودع.

## المقارنة قبل/بعد

استخدم أداة المرحلة الأولى التي حدثت لتسجيل أبعاد `.sectors-grid` و`.sector-card` و`.services-grid` و`.service-item` و`.train-card` و`.seo-tags` و`.stats-panel` و`.footer`.

### تنفيذ اختبار المصدر

```bash
node --test tests/cwv-content-visibility.test.js
```

### اختبار CLS على الهاتف مع صور مقارنة

```bash
cd tools
npm install
npx playwright install chromium
npm run audit -- --all-widths --compare-ads
```

قارن `details.json` والصور عند 360 و390 و412 بكسل، مع إجراء التمرير حتى النهاية ومع الإعلانات الفعلية وبدونها في الاختبار التشخيصي. وأعد الاختبار دون Cache إن أمكن، وبسرعات اتصال هاتفية متوسطة وبطيئة.

**معيار القبول:** اختفاء الانزياحات الناتجة عن تقديرات ارتفاع الأقسام والبطاقات، عدم حدوث ازدحام أفقي أو تغيّر مرئي غير مقصود، والحفاظ على بقية المحتوى والتفاعل والإعلانات. يجب متابعة Search Console لمدة كافية (قياس ميداني متحرك خلال 28 يومًا)، ولا تعني هذه التغييرات وحدها الوصول إلى CLS ≤ 0.10.
